## Executive Summary

The 2026-06-12 adversarial review produced 208 findings across 6 sections plus 2 orchestrator gap-closures (210 total): ~24 BUG/BUG-risk, ~17 PERF, 2 SEC, ~66 GOTCHA, ~10 BRITTLE, ~12 ABSTR, ~28 STYLE, ~49 TEST. Five cross-cutting themes emerged: (1) the test suite is wave-driven and coverage tracks ease not risk; (2) dead code is actively maintained; (3) a 10-second metronome amplifies every unmemoized derivation; (4) nothing validates boundaries; (5) on-screen aggregate numbers are not trustworthy.

This plan sequences remediation in the review's recommended dependency order, expressed as **11 implementation waves (W1–W11) plus Wave 0 infra**. Correctness and missing-coverage tests come first (W1–W6), perf and a11y next (W7–W8), the deletion sprint and scaffold DEV-gating after (W9), residual test-integrity cleanup (W10), and the large decompositions **last** (W11) — because the new regression tests (W1–W6, W10) are the safety net the refactors require, and W9 deletions shrink the refactor surface by thousands of lines. The systemic lazy-tooltip fix (prior #91) lands in W11 and migrates the ~20 always-mounted-tooltip tests; **all new tooltip tests written in W1–W6 use `fireEvent.pointerEnter` from the start** so they survive that fix.

This is a multi-sprint program, not a single sitting. Dispatch sizing below is by ~125k-token budget; the total is far larger than one agent, so engineers are split per wave by file cluster and tooling.

### CO-5 Hindsight / Lessons (≥5)

1. **Worktree land architecture:** worktree-isolated engineers can `stage` (commit to their branch) but their `mcp__aawm__land` (merge into the shared main repo) intermittently fails and **strands the main repo on a stray branch** (read-only main `.git` from the worktree sandbox). Adopted pattern: **engineers stage-only; an `ops` agent merges to develop** (ops has main-repo write access). This eliminated the land collisions/stranding that cost several recovery cycles mid-run.
2. **`tsc --noEmit` false-green:** TS project-reference incremental mode (`.tsbuildinfo`) **skips re-checking changed files**, so bare `tsc --noEmit` reported clean while 5 real type errors existed (a deleted-file import, fixture type-widening, stale route-id). Authoritative check is **`tsc -b --force`** — adopted for all QA/verify thereafter.
3. **A "test-env OOM" was a real product bug:** the full vitest suite couldn't complete because `use-table-url-state` (W6) had an **infinite render loop** (useState+useEffect mirroring URL search) that ballooned a worker to 3–6 GB — it would hang the live app too. Fixed with pure `useMemo` derivations. Static QA cannot catch runtime loops; suite-runnability failures deserve root-causing, not just "more memory".
4. **Generated-file drift hid a build break:** a running vite dev server kept re-dirtying `routeTree.gen.ts`; the committed tree still referenced a route file W6 had deleted (`$page.tsx`) → latent `vite build` failure invisible to vitest+static-QA. Generated files must be regenerated+committed with the change that moves routes.
5. **"Fix, don't suppress" drove real structure:** the stage hook blocks `react-refresh/only-export-components` warnings on staged files; per operator directive (no eslint-disable) this forced **extracting test-helper exports into `.ts` modules** (e.g. `phosphor-dashboard.testkit.ts`, `provider-identity.ts`) rather than disabling — a genuinely better outcome (engineers net-removed 2 disables across the run).
